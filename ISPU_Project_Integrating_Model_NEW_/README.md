# Final ISPU Project Integrating the HAR Model

This folder contains the complete final ISPU project integrating an INT8 Human Activity Recognition (HAR) neural network into the ISM330IS Intelligent Sensor Processing Unit (ISPU).

Unlike the standalone C files generated by ST Edge AI, this project includes the additional embedded application code required to acquire six-axis sensor data, preprocess and quantise the samples, execute the neural network, decode the prediction, and publish the result through the ISPU output registers.

## Target Hardware

- **ISPU sensor:** STMicroelectronics ISM330IS
- **Expansion board:** X-NUCLEO-IKS5A1
- **Adapter board:** STEVAL-MKI107A
- **Host board:** NUCLEO-F401RE
- **Deployment environment:** ST MEMS Studio and ST Edge AI
- **Compiler:** STRED GCC / ISPU Toolchain

## Human Activity Recognition Classes

The model recognises five activities:

| Class ID | Activity |
|---:|---|
| 0 | Brushing |
| 1 | Chopping |
| 2 | Cleaning |
| 3 | Idle |
| 4 | Pick and drop |

## Model Input

The neural network receives one window of six-axis inertial data.

| Property | Value |
|---|---|
| Input shape | `1 × 120 × 6` |
| Input type | Signed INT8 |
| Window length | 120 samples |
| Number of channels | 6 |
| Runtime sampling rate | 52 Hz |
| Window strategy | Non-overlapping |
| Channel order | `acc_x, acc_y, acc_z, gyro_x, gyro_y, gyro_z` |

Each sensor sample is arranged as:

```text
[acc_x, acc_y, acc_z, gyro_x, gyro_y, gyro_z]
```

The runtime application:

1. reads raw accelerometer and gyroscope values;
2. converts them to physical units;
3. applies the training-set mean and standard deviation;
4. quantises the normalised values to signed INT8;
5. fills the `120 × 6` input window;
6. executes the neural network;
7. selects the highest-scoring activity;
8. publishes the result through the ISPU output registers.

## Sensor Configuration

The ISM330IS configuration is defined in:

```text
ispu/conf.txt
```

The principal runtime settings are:

| Sensor | Configuration |
|---|---|
| Accelerometer ODR | 52 Hz |
| Accelerometer full scale | ±8 g |
| Gyroscope ODR | 52 Hz |
| Gyroscope full scale | ±2000 dps |
| Operating mode | High performance |

The accelerometer and gyroscope operate at a common output data rate so that one synchronized six-axis sample is supplied to the HAR application during each algorithm call.

## Output Registers

The application publishes the classification result and raw network scores through the ISPU data-output registers.

| Register | Meaning |
|---|---|
| `ISPU_DOUT_00` | Predicted activity class ID |
| `ISPU_DOUT_01` | Raw INT8 score of the predicted class |
| `ISPU_DOUT_02` | Raw INT8 score for class 0: brushing |
| `ISPU_DOUT_03` | Raw INT8 score for class 1: chopping |
| `ISPU_DOUT_04` | Raw INT8 score for class 2: cleaning |
| `ISPU_DOUT_05` | Raw INT8 score for class 3: idle |
| `ISPU_DOUT_06` | Raw INT8 score for class 4: pick and drop |
| `ISPU_DOUT_07` | Runtime status: `0` valid, `1` inference error |

Before the first complete input window is processed, `ISPU_DOUT_00` is set to `0xFF` to indicate that no prediction is yet available.

## Important Project Files

### `ispu/src/main.c`

This is the principal model-integration file. It contains the custom ISPU application code responsible for:

- sensor-data acquisition;
- accelerometer and gyroscope unit conversion;
- feature normalisation;
- INT8 input quantisation;
- creation of the `120 × 6` inference window;
- neural-network initialisation;
- invocation of `stai_network_run`;
- prediction decoding using argmax;
- writing predictions and scores to the output registers;
- runtime error reporting;
- ISPU interrupt generation.

### `ispu/src/network.c`

Contains the neural-network execution graph generated by ST Edge AI.

### `ispu/src/network_data.c`

Contains the trained and quantised neural-network parameters and weights.

### `ispu/make/Makefile`

Builds the complete ISPU application and generates the deployment files.

### `ispu/make/bin/ispu.json`

Register-configuration file used to program the compiled ISPU application and neural network onto the ISM330IS.

### `har_test_set.npz`

Contains the held-out HAR test dataset supplied for evaluation.

## Build Requirements

The following software is required:

- ST ISPU Toolchain 1.6.0 or a compatible version;
- `stred-gcc`;
- `stred-objcopy`;
- `stred-objdump`;
- `stred-size`;
- `ispu_gen`;
- GNU Make;
- ST MEMS Studio for programming and hardware interaction.

The ISPU toolchain executables and GNU Make must be available in the system `PATH`.

```cmd

```

Confirm that the tools are accessible:

```cmd
stred-gcc --version
make --version
ispu_gen --help
```

## Programming the ISM330IS

To deploy the application:

1. connect the NUCLEO-F401RE and X-NUCLEO-IKS5A1 hardware;
2. open ST MEMS Studio;
3. connect to the board;
4. select the ISM330IS sensor;
5. open the register-configuration or ISPU programming interface;
6. load:

```text
ispu/make/bin/ispu.json
```

7. program the configuration onto the ISM330IS;
8. start sensor acquisition;
9. monitor `ISPU_DOUT_00` to `ISPU_DOUT_07`.

A new classification result is generated after every complete 120-sample window.

At 52 Hz, one non-overlapping inference window represents approximately:

```text
120 / 52 ≈ 2.31 seconds
```

## Runtime Processing Flow

```text
ISM330IS accelerometer and gyroscope
                  │
                  ▼
       Raw six-axis sensor sample
                  │
                  ▼
      Physical-unit conversion
                  │
                  ▼
      Mean/std normalisation
                  │
                  ▼
          INT8 quantisation
                  │
                  ▼
       120 × 6 input buffering
                  │
                  ▼
       ST Edge AI neural network
                  │
                  ▼
          Five output scores
                  │
                  ▼
          Argmax classification
                  │
                  ▼
       ISPU_DOUT_00–ISPU_DOUT_07
```

## Memory-Constrained Runtime Design

The ISPU has limited data memory. The application therefore uses:

- the neural network’s allocated input buffer directly;
- one sample counter instead of an additional window buffer;
- signed INT8 model inputs and outputs;
- non-overlapping windows;
- direct output-register publication;
- no dynamically allocated memory.

This implementation avoids maintaining a second overlapping input window and reduces runtime RAM usage.

## Test Dataset

The supplied test dataset is:

```text
har_test_set.npz
```

It contains held-out input samples and expected activity labels for evaluating the HAR model.

The test data follows the same:

- 120-sample window length;
- six-channel ordering;
- activity-class mapping;
- preprocessing assumptions used during model development.
